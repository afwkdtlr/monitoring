# TEIA OPS 설명서

여섯 앱(CORE, MES, TOOL, PLC, POS, OFF)의 기동 상태, 소켓, PC 자원을 한 화면에서 보는 콘솔입니다. Java 8에서 동작하고, 화면 파일은 이 폴더 안의 `web`을 그대로 씁니다. 인터넷이나 CDN은 필요 없습니다.

브라우저 주소는 `http://127.0.0.1:18080` 입니다. 같은 PC의 다른 자리에서도 이 PC의 IP로 18080에 접속할 수 있습니다. 로그인 화면은 없습니다.

## 1. 다른 PC로 옮길 때

아래만 복사합니다.

| 경로 | 역할 |
| --- | --- |
| `start.bat`, `build.bat` | 실행, 컴파일 |
| `src` | 소스. `out`이 없으면 `start.bat`이 `build.bat`을 호출합니다 |
| `web` | 화면 |
| `config` | 최초 1회 기본값, Java 프로세스 조회 스크립트 |
| `lib\sqlite-jdbc-3.25.2.jar` | 설정 저장용. 이 파일은 꼭 같이 둡니다 |
| `data\ops.db` | 이 사이트의 앱 경로. 새 사이트면 빼고 가도 됩니다 |

`out`은 복사하지 않아도 됩니다. `overview-now.json`은 조회용 임시 파일이라 없어도 됩니다.

`data\ops.db`가 없으면 첫 실행 때 `config\apps.properties`의 여섯 앱과 JAR 폴더 `C:\SDOP\APP\jar`로 DB를 만듭니다. DB가 생긴 뒤에는 properties를 고쳐도 화면에 반영되지 않습니다. 경로는 **설정** 탭에서 바꿉니다.

JDK 경로는 사이트마다 다릅니다. `start.bat`과 `build.bat` 안의 `C:\Program Files\Java\jdk1.8.0_202\bin`을 그 PC의 Java 8 경로로 바꿉니다. 그 파일이 없으면 PATH의 `java`, `javac`를 사용합니다. 공장 PC에서는 보통 `C:\TEIA\bin\jdk\...\bin` 입니다.

## 2. 실행과 종료

`start.bat`을 실행합니다. 창에 `TEIA OPS http://127.0.0.1:18080`이 나오면 브라우저로 엽니다. 이 창을 닫으면 콘솔이 같이 종료됩니다. 라인 앱은 이 창과 별개로 계속 돌아갑니다.

포트를 바꾸려면 `start.bat` 마지막에 인자를 붙입니다.

```bat
start.bat --port 18081 --bind 127.0.0.1
```

`--config`는 최초 DB를 채울 때만 쓰는 시드 파일입니다.

## 3. 상태가 의미하는 것

3초마다 다시 읽습니다.

| 표시 | 뜻 |
| --- | --- |
| UP | 그 앱 프로세스가 있고, HTTP 포트가 1초 안에 `HTTP/`로 시작하는 응답을 줌 |
| 무응답 (DEGRADED) | 프로세스가 있거나 포트는 열려 있는데 HTTP 응답이 없음. 멈춰 있는 프로세스만 있어도 여기로 나옵니다 |
| DOWN | 프로세스도 없고 HTTP, JMX 포트도 닫혀 있음 |
| HTTP 응답 / 무응답 / 닫힘 | 위와 같은 HTTP 결과 |
| WS 열림 / 닫힘 | 웹소켓 포트가 열려 있는지만 표시. UP 판정에는 쓰지 않습니다 |
| Heap | JMX로 읽은 Java 힙 사용량. `Java heap space` 오류가 이 메모리입니다 |
| JMX 없음 | 프로세스는 HTTP에 응답하는데 JMX 포트가 닫힘. IntelliJ로 띄운 경우가 그렇습니다 |
| WS (호스트 목록의 메모리) | Windows가 그 프로세스에 잡아 둔 물리 메모리. Heap과 다른 값입니다 |

프로세스 이름은 `javaSdopCore.exe`처럼 설정한 이름과 맞으면 그 프로세스로 봅니다. 이름이 다르면 커맨드라인 식별자(세미콜론으로 여러 개)가 명령줄에 들어 있는 프로세스를 고릅니다. IntelliJ의 `CoreSpasApplication` 같은 이름이 이 용도입니다.

## 4. 화면

### 현황

CPU, 메모리, 디스크, UP인 앱 수, 앱 카드. 카드의 Heap은 JMX, WS 줄은 웹소켓 포트입니다.

### 앱 제어

| 버튼 | 동작 |
| --- | --- |
| 시작 | 설정에 적은 bat을 실행하고, HTTP 응답이 올 때까지 최대 120초 기다립니다. 이미 응답 중이면 두 번째 프로세스를 띄우지 않고 `이미 HTTP 응답 중`이라고 알려 줍니다. 프로세스는 있는데 응답이 없으면 시작하지 않습니다. 그때는 재시작을 누릅니다 |
| 정지 | 그 앱 프로세스만 `taskkill /F /T`로 끝냅니다. 콘솔 자신은 종료하지 않습니다 |
| 재시작 | 프로세스를 끝내고 **10초 기다린 뒤** bat을 실행합니다. 포트를 바로 다시 열면 점유 오류가 나기 때문입니다. HTTP 응답까지 확인합니다 |
| JAR 옮기기 | 그 앱의 개발 target JAR를 설정의 JAR 폴더로 복사합니다. 실행 중인 앱은 바뀌지 않습니다. 반영하려면 복사 후 재시작합니다 |

기동 bat은 창 제목을 주고 `javaw` 계열 exe로 JVM만 띄운 뒤 cmd는 닫히게 되어 있습니다. `javaSdopCore.exe` 같은 파일은 같은 JDK의 `javaw.exe`를 복사한 것입니다. 이름이 다르면 Windows 방화벽이 프로그램마다 한 번씩 허용을 묻습니다. 허용 규칙은 PC에 저장되므로, 폴더를 다른 PC로 옮겨도 그 PC에서는 다시 한 번 묻습니다.

### 소켓

앱을 고르고 **조회**를 누릅니다. 목록은 그 앱의 웹소켓 포트로 `SOCKET_SET`을 보내 가져옵니다.

**기동**은 엔진의 `SK_STAT`입니다. 서버 소켓은 포트만 열려도 RUN인 경우가 있어서, 상대가 붙어 있다는 뜻은 아닙니다.

**연결**은 채널을 세어 표시합니다.

| 연결 | 뜻 |
| --- | --- |
| 확인중 | 채널 조회가 아직 끝나지 않음 |
| 연결, 연결 N | ACTIVE 채널이 있음. 숫자는 서버에 붙은 연결 수 |
| 끊김 | 클라이언트인데 기동은 RUN이고 ACTIVE 채널은 없음 |
| 대기 | 서버인데 기동은 RUN이고 붙은 연결은 없음 |
| 정지 | 기동이 RUN이 아니고 ACTIVE 채널도 없음 |
| 확인실패 | 채널 조회가 실패함 |

행을 누르면 오른쪽에 채널이 나옵니다. **수신**, **발신**은 선택한 채널의 전문 이력입니다. 이력이 비어 있으면 `이력 없음`입니다. **Ping**은 그 소켓 IP로 ICMP입니다. `0.0.0.0`은 항상 NO입니다. **스레드**는 이름, 상태, 번호만 최대 80줄 보여 줍니다.

**시작**, **정지**는 선택한 소켓(자식이면 SUB_START, SUB_STOP)에 내립니다. **Client 재접속**은 클라이언트의 채널만 닫습니다. 다시 붙는 것은 그 클라이언트의 재접속 루프입니다. 앱 UP/DOWN과는 별개입니다.

01:50~03:50에는 엔진이 `SK_STAT` 갱신을 멈추므로, 그 시간의 기동 표시는 실제와 다를 수 있습니다. 연결 칸은 채널을 직접 세므로 그 영향이 적습니다.

### 호스트

드라이브 사용량, `java`로 시작하는 프로세스, 이 화면에서 누른 시작/정지/재시작/JAR 옮기기 기록. 기록은 메모리에만 있고 콘솔을 끄면 사라집니다. 최근 30건이 보입니다.

### 설정

저장하면 `data\ops.db`에 들어가고, 콘솔을 재시작하지 않아도 바로 그 경로를 봅니다.

| 항목 | 넣는 값 |
| --- | --- |
| JAR 옮기기 폴더 | bat이 `-jar`로 읽는 폴더. 이 사이트는 `C:\SDOP\APP\jar` |
| ID | 영문, 숫자, `_`, `-`. 최대 32자. 화면 주소와 버튼이 이 값을 씁니다 |
| 표시 이름 | 카드에 나오는 이름 |
| HTTP, WS, JMX | 1~65535 |
| 프로세스 이름 | 운영에서 띄운 exe 이름. 예: `javaSdopCore.exe` |
| 기동 bat | 시작/재시작이 실행할 bat의 전체 경로 |
| 커맨드라인 식별자 | exe 이름이 안 맞을 때의 보조 조건. `com.spas.core;CoreSpasApplication`처럼 세미콜론으로 구분 |
| 개발 target JAR | Maven `target`의 fat JAR 전체 경로. JAR 옮기기의 원본 |

**행 추가** 후 ID부터 채우고 **저장**합니다. 잘못된 ID나 포트는 저장되지 않고, 기존 여섯 앱도 그대로 남습니다. 행 삭제는 저장해야 DB에 반영됩니다.

## 6. 자주 보는 메시지

| 메시지 | 의미 |
| --- | --- |
| 이미 HTTP 응답 중 pid N | 시작을 눌렀지만 이미 정상. 추가 기동 없음 |
| 프로세스는 있으나 HTTP 응답이 없습니다. 재시작하세요 | 멈춰 있는 프로세스가 포트를 잡고 있음 |
| 120초 안에 HTTP 응답이 없습니다 | bat은 실행됐으나 HTTP가 안 열림. bat 경로, JAR, 포트 점유를 확인 |
| 기동 스크립트가 없습니다 | 설정의 bat 경로가 틀림 |
| target JAR가 없습니다 | 개발 PC에서 패키징이 안 됐거나 경로가 틀림 |
| 종료 후 10초 대기, HTTP 응답 확인 pid N | 재시작이 끝난 정상 메시지 |
